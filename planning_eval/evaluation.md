# Planning Evaluation

This folder contains the evaluation suite for the Sterling & Vance Bank Planning Agent.

## Evaluation Requests

Realistic banking investigation requests will be stored in:

```text
test_requests.json
```

The test suite contains real requests designed to exercise the different planning behaviors and provide a fair comparison between the supported methods.

The test cases should include:

* cases that favor decomposition-first planning
* cases where dynamic decomposition can react to new observations
* cases requiring lookahead or comparison of multiple alternatives
* cases where repeated attempts and cross-trial memory are useful
* cases where grounded external feedback is important for the final decision

## Evaluation Runner

```text
run_evaluation.py
```

The evaluation runner executes the applicable planning methods against the evaluation requests and records their results and execution traces.

## Metrics

```text
metrics.py
```

This module calculates the evaluation metrics from the collected results.

The main metrics are:

* task success / accuracy
* total LLM calls
* total tokens
* latency
* estimated cost per run

## Artifacts

Each evaluation run will save its execution traces under:

```text
artifacts/
```

The artifacts provide the traces and evidence supporting the comparison tables.

## Method Selection

The final planning architecture will be selected based on the evaluation results.

Each method will be assigned to the sub-task types where it provides the best trade-off between:

* correctness
* task success
* reasoning quality
* LLM calls
* token usage
* latency
* cost

The selected method for each sub-task will be justified using the comparison results.
